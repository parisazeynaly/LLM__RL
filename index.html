Causal Inference × Reinforcement Learning × Security Testing

Two research questions, one empirical thread

LLM safety training is only as good as the tests that probe it. If a security‑testing agent can't tell why a guardrail was bypassed, it wastes effort and gives a false sense of security about what's actually been checked.

Everything in the thesis builds toward answering two nested questions, tested against a real target model (Llama‑4‑Scout) on 104 held‑out AdvBench prompts across three seeds.

RQ1 · Reinforcement Learning × Security Testing

Is RL effective for testing LLM security?

Comparing an RL‑based mutation strategy (RLBreaker) against static, dataset‑based prompting drawn from DAN (Shen et al., arXiv:2308.03825, 2023). The result: only a marginal difference on a well‑aligned target — adaptive mutation alone isn't the advantage it's assumed to be.

RQ2 · Causal Inference × Reinforcement Learning

Is Causal RL better than RL alone?

Causal RL — reinforcement learning combined with causal knowledge extracted via a COAT‑style causal‑discovery pipeline — replaces sparse pass/fail feedback with a dense, causally‑derived reward. RQ2 tests whether this combination outperforms standard RL on both effectiveness and cost.

Both RQs are evaluated on the same two axes used throughout the RL‑based security‑testing literature (RLBreaker, MazeBreaker): a success‑rate metric (ASR) and a cost metric — training and inference time / API overhead.

3.18× improvement over the RL‑only baseline, with lower variance across seeds (±1.67 vs ±3.21) and a 41.8% reduction in training‑time API calls.

  • Finding 1 — RL‑only mutation barely beats static prompting on a well‑aligned target model, consistent with a credit‑assignment bottleneck.
  • Finding 2 — Dense, causally‑derived reward shaping resolves that bottleneck and generalizes zero‑shot to a different model family (45.2% ASR on Qwen‑3).
  • Open question — query‑count‑to‑success is statistically identical between methods, suggesting the causal signal changes which prompts succeed rather than how fast — flagged explicitly as unresolved in the thesis.

Ethics & responsible disclosure

This work is defensive AI‑safety evaluation research, not an offensive toolkit. All experiments run against the public AdvBench benchmark under controlled, non‑deployed conditions; no successful bypass prompts, model outputs, or exploit templates are published in the thesis, the codebase, or this site. The goal is to measure and explain alignment failure modes so they can be fixed — consistent with standard practice in the LLM security‑testing literature (e.g. HarmBench, RLBreaker).
