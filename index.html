Making LLM red‑teaming causally accountable, not just adaptive.

My thesis, Security Testing of Large Language Models via Causal Reinforcement Learning, asks which structural properties of a prompt actually cause a jailbreak — then uses that causal graph to guide a reinforcement‑learning agent, instead of relying on sparse pass/fail signals alone.

Thesis

Two questions, tested against a real target model

The thesis is built around a deliberately narrow empirical comparison, evaluated against Llama‑3.3‑70B on 104 held‑out AdvBench prompts across three seeds.

RQ1

Is RL more effective than static prompting?

Comparing an RL mutation policy (RLBreaker) against a static template baseline (DAN). The result: only a marginal difference on a well‑aligned target — adaptive mutation alone isn't the advantage it's assumed to be.

RQ2

Does causal structure improve on RL alone?

Embedding an FCI‑discovered causal graph into the reward and action space of the same RL agent — testing whether knowing why a mutation worked beats sparse pass/fail feedback.

3.18× improvement over the RL‑only baseline, with lower variance across seeds (±1.67 vs ±3.21) and a 41.8% reduction in training‑time API calls.

  • Finding 1 — RL‑only mutation barely beats static prompting on a well‑aligned 70B model, consistent with a credit‑assignment bottleneck.
  • Finding 2 — Dense, causally‑derived reward shaping resolves that bottleneck and generalizes zero‑shot to a different model family (45.2% ASR on Qwen‑3).
  • Open question — query‑count‑to‑success is statistically identical between methods, suggesting the causal signal changes which prompts succeed rather than how fast — flagged explicitly as unresolved in the thesis.
